# Миграция терминов из legacy-документов

Type: grilling
Status: resolved
Blocked by: 01, 03, 04, 05, 07, 08, 09, 10, 11, 12, 13, 14

## Question

Определить канонический словарь v1 и правила миграции терминов из legacy-документов, включая конфликтующие или устаревшие названия, чтобы новые спецификации и CONTEXT.md использовали единый доменный язык.

## Answer
Канонический термин для `capital ship` — **крупный корабль** (`Large Ship`): крупный боевой юнит, занимающий один гекс, с массой и курсом. «Капитальный корабль», `капшип` и `capital ship` запрещены в нормативных правилах; они допустимы только как legacy-синонимы или в обсуждении миграции.

**Эскадрилья** (`Squadron`) — единственный канонический термин для стека малых аппаратов. «Звено», «москиты» и «москитный флот» считаются устаревшими названиями и не используются в новых документах.

В v1 условие победы — полное уничтожение всех юнитов стороны. Понятие «боеспособный юнит» и победа по отсутствию боеспособных юнитов относятся к v2; ничья в v1 не предусмотрена.

Новые спецификации и `CONTEXT.md` используют только канонический словарь. Legacy-документы сохраняются как справочные, получают указатели на канонические документы и не переписываются полностью; при конфликте приоритет имеют спецификации v1.

### Правила миграции

- Нормативные ссылки legacy-документов ведут на соответствующий документ `docs/specs/v1/`; legacy-текст остаётся историческим и не переписывается.
- При переносе правила заменять legacy-термины каноническими по смыслу, а не механически.
- «Корабль» использовать только как общий неформальный термин или уточнять до «крупного корабля»; юнит малых аппаратов всегда называть «эскадрильей».
- «Живой» и «боеспособный» не использовать для условия победы; применять «неуничтоженный юнит» только при необходимости описать состояние.
- В спорных случаях выбирать термин из `CONTEXT.md`, затем добавлять уточнение в нормативную спецификацию.
